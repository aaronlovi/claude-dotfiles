# Elixir Projects

- Add `{:excoveralls, "~> 0.18", only: :test}` for coverage reporting. Configure with `test_coverage: [tool: ExCoveralls]` in `project/0` and coveralls tasks in `preferred_envs` in `cli/0`.
- Add a `precommit` alias in `mix.exs` that runs in this order: `deps.unlock --unused`, `format`, `compile --warning-as-errors`, `credo`, `sobelow --config`, `test`. Run `mix precommit` before every commit. Always commit `mix.lock` alongside dependency changes.
- Add `{:credo, "~> 1.7", only: [:dev, :test], runtime: false}` and `{:sobelow, "~> 0.13", only: [:dev, :test], runtime: false}`. **In `.credo.exs`, always use `checks: [...]` (a list) to add or configure checks — this merges with Credo's defaults. Never use `checks: %{enabled: [...]}` (a map) — the map format silently replaces the entire default check list, disabling all built-in checks except those explicitly listed.**
- At the end of development, verify the Docker build passes with `docker build -t <name> .` before considering the project done.
- **When a GenServer does database writes inside `handle_call/3` or `handle_info/2`, use `Ecto.Adapters.SQL.Sandbox.allow/3` in tests to grant the GenServer process access to the test's sandbox connection.** DB writes inside GenServer callbacks are normal and common — the GenServer serialises state and DB writes together atomically. The sandbox issue is that the GenServer process doesn't share the test's connection by default; `allow/3` fixes this. Pattern: after obtaining the GenServer's PID (e.g. via `find_or_create`), call `Ecto.Adapters.SQL.Sandbox.allow(Repo, self(), pid)` before exercising the GenServer in the test. Alternatively, DB writes can be done in the caller's process (before sending the message or after receiving the reply) — this avoids the `allow` setup but adds complexity to production code and creates a brief window where in-memory state and DB are out of sync.
- **Add database comments to all Ecto migrations.** Every `create table` call must include a `comment` option on the table itself and on each column. Use concise, human-readable descriptions. For `alter table` calls that add new columns, add `comment` to each new column. Example: `add :email, :string, null: false, comment: "Primary email address for login and notifications"`.
- **Use structured (JSON) logging in all environments.** Add `{:logger_json, "~> 7.0"}` (no `only:` restriction) and configure it in `config/config.exs` as the default handler: `config :logger, :default_handler, formatter: {LoggerJSON.Formatters.Basic, metadata: :all}`. Do not add a plain-text formatter override in `dev.exs`. Configure the credo check `{Credo.Check.Warning.MissedMetadataKeyInLoggerConfig, [metadata_keys: :all]}` in `.credo.exs` to silence false positives. The field is named `severity` (not `level`) — this is intentional and follows Google Cloud Logging convention.
- **Log every API request and response.** For Phoenix apps, add a `Plugs.RequestLogger` plug to all API pipelines. On ingress it logs method, path, query string, and merged params; on egress (via `register_before_send/2`) it logs status and JSON-decoded response body. **WARNING: sensitive values (client secrets, tokens) appear in plaintext — do NOT use in production. Dev/test only.**
- **Use dotenvy for environment variable loading with no defaults.** Add `{:dotenvy, "~> 1.1"}` (no `only:` restriction). In `config/runtime.exs`, load env vars conditionally: `config_env() == :dev -> source!([".env", System.get_env()])`, `config_env() == :prod -> source!([System.get_env()])`, test uses static config in `test.exs`. Use `env!("VAR_NAME", :type)` for every variable — **never pass a default value**. Never use `System.get_env()` after `source!()` — it only reads the OS environment and silently misses dotenvy-loaded values. If any variable is missing, the app must refuse to start. The `.env` file is where dev defaults live, not in `runtime.exs` or `config.exs`. Add `.env` to `.gitignore` and maintain a `.env.example` with all keys documented and example values. Test config goes in `config/test.exs` as static values (tests should not depend on `.env`). Do not put any application configuration in `config.exs` that should come from env vars — `config.exs` is only for compile-time framework settings (endpoint, logger, phoenix json library).
- **Add CORS support with Corsica.** Add `{:corsica, "~> 2.0"}` and wire it in `endpoint.ex` (before the router), not in router pipelines: `plug Corsica, origins: "*", allow_headers: :all, max_age: 3600`. Endpoint placement is required so OPTIONS preflight requests are intercepted before routing (no router route matches OPTIONS). Use `origins: "*"` — the atom `:all` is invalid in Corsica 2.x and raises a `FunctionClauseError`.
- **Use `Req` for HTTP requests, not `:httpc`.** Add `{:req, "~> 0.5"}`. `Req` is the standard Elixir HTTP client with connection pooling, JSON decoding, and retry support. `:httpc` is bare-bones Erlang and should not be used.
- **Secrets and keys as file paths, not inline values.** Sensitive values like private keys should be stored as files, with the env var pointing to the file path (e.g., `JWT_PRIVATE_KEY_FILE=priv/dev_signing_key.pem`). The app reads the file at startup. This avoids multi-line values in `.env` files and matches how Kubernetes secrets are mounted. Add `*.pem` to `.gitignore`. Include key generation instructions in `README.md`.
- **GenServer logging.** Every GenServer must log on `init/1` with key config values (so operators can verify the process started and what it's configured with). Log on entering significant async operations (fetches, refreshes) and on both success and failure outcomes. `rescue`/`catch` blocks must always log — never swallow errors silently.
- **Crash fast on missing required config.** If a process cannot function without a configuration value, `init/1` must return `{:stop, reason}` — do not fall back to a "disabled" mode. This applies in all environments including dev and test.
- **Use ETS for high-read GenServer state.** When a GenServer's state is read frequently and written rarely (e.g., cached config, JWKS keys), store the data in an ETS table with `read_concurrency: true`. Public API functions read directly from ETS; the GenServer only handles writes. This eliminates mailbox serialization under concurrent load.
- **Comment all private functions.** Every `defp` gets a 1-2 line comment above it explaining what it does.
- **Extract shared private helpers into utility modules.** When a private function is duplicated across two or more modules, extract it into a shared utility module under `MyApp.Utils` (e.g., `MyApp.Utils.EtsCache`). Before adding a private helper, consider whether it's general-purpose enough to belong in a utility module.
- **Keep function nesting depth at 2 or below** (Credo's default max). Each `if`/`case`/`cond`/`with`/`fn` adds a level; `case` inside `if` inside `def` is already at 3. When nesting exceeds 2, extract the inner logic into a named private helper. Common patterns that hit the limit: `case` inside `if` validation guards, `fn` callbacks inside `with`/`Multi.run`, and nested `case` chains. Flatten with `with`, early returns, or helper extraction.
- **Always put the positive condition first in `if`/`else`.** Never write `if not x do ... else ... end` — Credo flags `Credo.Check.Refactor.NegatedConditionsInUnless` and `NegatedConditionsWithElse`. Swap the branches: `if x do ... else ... end`.
- **Use `== []` or `!= []` for empty list checks, not `length/1`.** `length/1` traverses the entire list in O(n); comparing against `[]` is O(1). Credo flags this via `Credo.Check.Warning.ExpensiveEmptyEnumCheck`. For the same reason, prefer `Enum.map_join/3` over `Enum.map/2 |> Enum.join/2` — it's a single pass.
- **Avoid SELECT-before-write round trips when Ecto can do it in one query.** For idempotent deletes, use `Repo.delete_all(from(u in User, where: u.id == ^id, select: u))` instead of `Repo.get` + `Repo.delete` — single query, returns the full struct via `DELETE ... RETURNING *`, and naturally handles not-found (`{0, []}`) without raising. Same principle applies to conditional updates: prefer `Repo.update_all` with `select` over a lookup followed by `Repo.update` when you don't need changeset callbacks.
- **Wrap every public context function and DB-touching private helper with `context_log/3`.** Use a shared `MyApp.Utils.ContextLog` module that provides `context_log(function_name, metadata, fun)`. This single call handles entry logging (info), outcome logging (info for success, warning for errors/not-found), and exception logging (error + re-raise). The `fn ->` block adds one nesting level — if the body would exceed depth 2, extract the inner logic into a private `_impl` helper. Never use separate `Logger.info` entry lines or manual outcome logging in context functions — `context_log` replaces both.
- **Extract `Ecto.Multi.run` callbacks into named private functions.** Never put DB operations inside inline anonymous functions in Multi pipelines. Extract each step into a `defp` wrapped with `context_log/3`. The `Multi.run` lambda should just delegate: `fn _repo, _changes -> my_step(args) end`. This gives meaningful function names in stack traces, consistent logging per step, and keeps the Multi pipeline readable as a sequence of step names. Ignore the `repo` parameter — use the module-level `Repo` alias instead.
- **Log at warn level for all error outcomes in context functions.** This includes: changeset validation failures (bad input from callers), constraint violations on insert/update after app-level checks, transaction failures (`Ecto.Multi` errors), not-found lookups, and delete failures. These all represent conditions operators should see — bad request patterns, TOCTOU races, schema drift, or DB issues. Include the entity ID and `inspect(changeset.errors)` or `inspect(reason)` as structured metadata. The `context_log/3` wrapper handles this automatically via outcome pattern matching.
- **Use `Application.fetch_env!/2`, not `Application.get_env/3`.** Config values should always be present — never provide defaults or check for nil. If a value is missing, the app should crash immediately with a clear error. The only exception is `Application.get_env` for truly optional settings like `dns_cluster_query` where `nil` is a valid state.
- **No compile-time metaprogramming in tests.** `for` loops for data-driven tests are fine — they keep tests DRY and readable. Do not use `quote`, `unquote`, or `Macro.escape` to generate tests at compile time; there is almost always a simpler data-driven approach using `for` with a list of `{input, expected}` tuples. For shared setup, extract a helper function called at runtime. Keep tests readable without requiring knowledge of Elixir metaprogramming.
- **Do not test log output.** Never write tests that assert on Logger output (via `capture_log`, `with_log`, or custom handlers). Logging is a side effect for operators, not a contract — if the code compiles and the function works, the log call executes. Tests that verify log strings are tautological and brittle. Test the actual behavior (return values, database state, HTTP responses, telemetry events) instead.
- **Tests must use context modules, not raw Ecto.** Tests should never call `Repo.insert`, `Repo.get`, `Repo.one`, `Ecto.Query.where`, or other Ecto functions directly. Always go through the application's context modules (e.g., `Accounts.create_user`, `RBAC.get_role`). The context layer is the public API — tests that bypass it are testing implementation details and won't catch regressions in the context functions. The only exception is `Repo.all(Schema)` for asserting that a table is empty (e.g., `assert Repo.all(RolePrivilege) == []` for cascade-delete verification), where no context function exists for that query.
- **Never leak internal details in API error responses.** Error responses must return generic messages (e.g., `"Validation failed"`, `"Conflict"`, `"Internal server error"`). Never expose changeset field names, constraint details, schema structure, or stack traces. Log detailed error information server-side for debugging — use Logger level to control verbosity across environments.
- **Hash all credentials at rest.** Passwords, client secrets, API keys, and any other credentials must be hashed with an adaptive slow hash algorithm (bcrypt or Argon2) before storage. Never store or compare credentials in plaintext. Never log credential values.
- **Document function options.** When a public function accepts an `opts` keyword list, the `@doc` must list each supported option with its type, default value, and purpose.
- **Snake_case everywhere in JSON APIs.** Phoenix JSON views must use snake_case keys matching Ecto field names. Request body params, query params, and response keys all use snake_case. Never convert to camelCase at the API boundary — keep snake_case end-to-end. This avoids the common bug where inputs use one case and outputs use another.
- **Add `{:dialyxir, "~> 1.4", only: [:dev, :test], runtime: false}` for static type analysis.** Configure with `flags: [:error_handling, :underspecs, :no_opaque]` to suppress false positives from Ecto.Multi opaque types. Optionally add `"dialyzer"` to the precommit alias if the project uses it. **Always include `plt_add_apps: [:ex_unit]`** so dialyzer recognizes ExUnit internals referenced by test support modules (`ConnCase`, `DataCase`). Without this, dialyzer reports false `unknown_function` errors for `ExUnit.Callbacks` and `ExUnit.CaseTemplate` functions.
- **Add unique constraints on external identifiers.** Columns that identify external entities (`external_id`, `client_id`, etc.) must have a unique index. Use a partial index (`WHERE col IS NOT NULL`) when the column is nullable. Without this, `Repo.get_by` crashes with `Ecto.MultipleResultsError` when duplicates exist — a 500 error in production.
- **Extract test factories into a shared module.** Create a `TestFactories` module in `test/support/` with helpers like `create_user!`, `create_role!`, `valid_user_attrs`. Import it via `DataCase` and `ConnCase` so all tests get them automatically. Keep test-specific variants as local overrides using `import TestFactories, except: [create_user!: 1]`.
